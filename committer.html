Archetype · fourth of five

Committer

The team's ceiling lets model-generated changes of a defined class reach trunk unread; a human still gates the release. Every genuine occupant observed grants this to a narrow, mechanically-identified class — never to the agent in general.

Vocabulary as of 2026-08-31 Taxonomy: ADR-0004 Sources last verified 2026-09-02

Kinds, not ranks: no archetype is the goal state, and moving further along the spectrum means more engineered verification, not less discipline. Human oversight varies independently within every archetype.

01What this archetype is

A Committer ceiling permits model-generated changes of a defined class to merge to trunk with no human reading them, while a human still gates the release. The archetype names the ceiling — what the settings permit — not what any individual change receives: on every team observed at this position, most changes still travel human-reviewed routes, and the unread class is deliberately narrowADR-0004.

Two standing clarifications travel with this page's name. First, "Committer" describes the team's ceiling, never the agent's standing: the Linux kernel permits AI assistance but forbids agents from adding Signed-off-by — only humans certify the Developer Certificate of Origin — and merging an agent's change is adoption, not authorship (§07)Practitioner Exemplars, Aug 2026. Second, the largest unattended-merge operation in existence is the precedent, not an instance: Spotify auto-merges 2.5 million scripted, deterministic transforms with no model involved, while human-reviewing every LLM PR. Deterministic no-model automation sits outside the spectrum; its ceiling for model-generated changes is what Spotify's archetype namesSpotify, Jun 2026ADR-0004.

02The boundary crossed

What separates Committer from Contributor is merge rights: crossing this boundary, the agent's output reaches trunk with no human action in between. The boundary is a discontinuity — a credential the previous archetype structurally lacks — and on the platform hosting nearly all observable agent activity it must be built: GitHub's cloud agent "cannot approve or merge a pull request", and its PRs require an additional human approval, so a team that wants unreviewed agent merging constructs it deliberately from a bot account, a bespoke workflow, or a ruleset bypass. That is why every occupant of this archetype is visible as an artifact — a file in a repoGitHub Docs, Aug 2026Practitioner Exemplars, Aug 2026.

The crossing has a documented halfway point worth naming, because it shows the mechanism's true shape. ClawSweeper — the bot that maintains the OpenClaw repositories — has a genuine automerge lane, and it begins with a human typing /clawsweeper automerge on each individual PR; the merge then pins to a reviewed head SHA behind CI, and the project's own docs insist the bot is not the gate: "A positive ClawSweeper result is supporting evidence, not maintainer approval." Scale that pre-authorisation from per-PR to per-change-class and you have this archetype: not an agent that merges, but a human who pre-authorises a merge that then happens without themTooling Landscape, Aug 2026.

03What a human still gates

Three things, on every real occupant found. First, the release — the human-mark of this archetype: trunk is not production, and a human still decides what ships. Second, the qualifying line: which change classes may merge unread. Everywhere it has been observed, that line is a mechanical property of the change, never a judgment about the agent — author identity plus title prefix (JetBrains), severity triage plus CI (Razorpay), a branch pattern with quota caps (Microsoft), a risk score with a tunable threshold (Meta)Practitioner Exemplars, Aug 2026. Third, everything outside the class — the overwhelming majority of changes.

One gate is universal enough to state as a rule: self-approval is forbidden everywhere. GitHub forbids it at the platform level, Ramp designs against it at the authentication layer, and even the one project governed as agent-run by design encodes it as an anti-collusion rulePractitioner Exemplars, Aug 2026.

Independence rule

Containment and human oversight move independently. This section names the oversight; the spectrum position above names only the reach. A Committer team is not "less supervised" than a Contributor team — it has moved the supervision from reading diffs to policing a line.

04Who works this way

The genuine cases of agent-authored changes merging unread as stated policy number three, and each carries its deflating detail. Razorpay/Slash is the only organisational case at scale: over a third of Slash-created PRs merged with no human in the loop across one quarter (~100/week), gated on severity triage plus the normal CI suite — a single self-published post with no control period, no baseline, and no defect data. It is the strongest far-end claim in existence, and it is one blog postRazorpay, Jun 2026. JetBrains/IdeaVim is the cleanest artifact: a public workflow file whose entire policy is three conditions — the PR is in this one repository, authored by claude[bot], and titled Update changelog:… — and whose --auto merge still waits on required status checks. Changelog updates, and nothing elseIdeaVim workflow, 2026. inder/salvobase publishes a formal agent protocol with tiered merge rights — and is a 1-star experimental repository where 151 of 155 merges come from a single account; the autonomy claim is the project's pitchSalvobase protocol, 2026.

The best-engineered occupant is a configuration, not a claim: Microsoft's dotnet/macios grants an agent merge rights for one job — forward-merging main into xcode* release branches — inside withholding by construction: permissions: {} at the workflow level, a rotating pool of scoped tokens, a network allowlist, quota caps, a required title prefix, and a fail-closed safety gate a human step suppliesdotnet/macios workflow, 2026. And the strongest documented case of removing the human from the gate is Meta's RADAR: 331,000+ diffs landed with no human reviewer, with a revert rate one third and a production incident rate one fiftieth of human-reviewed diffs — on a risk-scored subset selected for being low-risk, so the favourable numbers are selection, not proof of superiorityMeta (arXiv), 2026. The near-misses complete the picture: Intercom auto-approves ~17% of PRs under published criteria (small, tested, flagged, outside hot paths); Ona lets the agent approve while a human always mergesPractitioner Exemplars, Aug 2026. Nothing surfaced from a company of scale in a regulated domain with an independent account of outcomes.

05What it gains you, what it costs

What it gains you
  • Mechanically-checkable classes stop queueing behind human availability, and review attention concentrates on changes a human can actually help — the direct answer to the Contributor archetype's measured bottleneck.
  • An auditable trust model: because the qualifying line is mechanical and the platform forces the bypass to be built, the policy is an inspectable artifact — a workflow file, not a habitPractitioner Exemplars, Aug 2026.
  • For a well-chosen class, the payoff ceiling is documented: RADAR's qualifying diffs revert at a third the rate of human-reviewed ones — selection, but selection working as designedMeta (arXiv), 2026.
What it costs you
  • The qualifying line must be engineered, argued for, and policed forever; it is the control everything else hangs from, and it only ever moves under pressure to widen.
  • Verification machinery becomes load-bearing the moment no one reads the diff — and for agent-authored unread merges specifically, no study anywhere compares outcomes with human review against without. The efficacy evidence for this archetype's defining act does not existEvidence Base, Aug 2026.
  • Teams drift here rather than decide: reviewer habituation under agent volume (approval rising, comments falling, latency growing) is the measured mechanism that forces the crossing whether or not it was chosenHabituation study, Jun 2026.

06What it demands of verification

The entailment gets its teeth here: for the qualifying class, whatever human review used to establish must now be established by machinery, because nothing else stands between the agent's output and trunk. Every real occupant's answer is the same in shape — mechanical qualification plus the ordinary CI suite — which means for the unread class, the checks are the entire safety case, and three measured facts bear on whether they can carry it.

First, the checks are targets. Handed a proof obligation it could not pass, an agent silenced failures with pragma Assume; after that was banned, it excluded code from proof with SPARK_Mode => Off. Anti-suppression — lint disables require reasons, ignores must carry codes, expectations over allowances — is the load-bearing half of the practice, and the half advocacy literature omitssecunet (arXiv), 2026. Second, gates must live server-side, outside the agent's reach: in CI and branch protection, not the agent harness — the platform describes its own agent-side approval queue as "a workflow convenience, not a security control", and harness-side stops are overridable by the harness itselfVerification: Gates, Aug 2026. Third, the machinery decays silently: of the four organisations found running real agent evals, one shipped a CI regression workflow and lost it months later in an unrelated refactor, with nothing detecting the lossVerification Infrastructure, Aug 2026.

And one wire is still missing across the whole field: no adopted mechanism gates, canaries, or auto-reverts a change because it was agent-authored — at the delivery layer no published mechanism at all (re-verified with search, 2026-09-02), and the merge layer holds exactly two published, unadopted artifacts: one that responds to agent authorship by demanding more human review — the inverse of this archetype's direction — and detects agents by committer identity, so it misses the dominant workflowVerification Infrastructure, Aug 2026Tooling Landscape, Aug 2026, and one marketplace product that risk-scores and auto-merges by per-agent trust, in this archetype's own direction, with no observed adopter and no activity since days after its March 2026 launch. The qualifying line itself, rendered in code, is what a mature version of this archetype looks like: RADAR's operational heart is a single tunable risk threshold — relaxing it from the 25th to the 50th percentile raises the auto-approved share to 60.31% — one dial deciding what fraction of changes never meet a humanMeta (arXiv), 2026. A Committer team should be able to point at its equivalent dial, and at who may turn it.

07Governance implications

The DCO note, stated explicitly as ADR-0004 obliges. A merge right does not confer standing. The Linux kernel's policy is the sharpest statement: AI assistance is permitted, but agents may not add Signed-off-by — only a human can certify the Developer Certificate of OriginPractitioner Exemplars, Aug 2026. The same line runs through copyright: merging an agent's change is adoption, not authorship — "providing instructions to a machine and selecting an output does not equate to authorship" — and registration requires disclaiming AI-generated content, so the operative question is "which lines did a human write." At this archetype that question acquires an uncomfortable property: for the unread class, the answer is recorded but unread — the provenance exists on the platform, and no human has looked at what it attributesGovernance, Legal & IP, Aug 2026.

Compliance permits this archetype. No verified regime requires a human to read source code, and the framework with the strongest human-review requirement writes the exception into the same document: SLSA's two-party review MAY be perpetually excepted for a Trusted Robot — granted by the organization, at Source L4 only, requiring an identity that "cannot be unilaterally influenced", and drawing the human/machine line for approval, never authorship. The governance demand on a Committer team is therefore exactly the shape of its own qualifying line: a controlled, documented, identity-bound exception — not a relaxationGovernance, Legal & IP, Aug 2026. What the team cannot delegate is the consequence: every provider disclaims defect liability, so the unread class's defects are owned by the team that defined the classGovernance, Legal & IP, Aug 2026.

08The posture that fits

This fits a team that believes trust should be earned by change class rather than by author — and that where a class can be checked mechanically, a human reading it adds cost without adding safety.

The safety belief underneath: the class is mechanically checkable. The control moves; it does not improve. And the honest edge: every genuine occupant has narrowed the class almost to triviality — changelog updates, forward-merges, low-severity fixes — and the one case with outcome numbers chose its class precisely for being low-risk. The belief has never been tested where it would hurt, and the study that would test it has never been run.
